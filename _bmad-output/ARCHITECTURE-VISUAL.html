local-whisper (VocaMac) — Architecture, Visually

How a dictation actually moves through the app, what Command Mode does differently, which model files exist where, and what does — and never does — touch disk or network.

Grounded against Sources/VocaMac/** and _bmad-output/planning-artifacts/architecture.md; where the two disagreed, the code won. Companion file: ARCHITECTURE-VISUAL.md (same content, git-diffable text form).

1 Big picture — what's actually running

VocaMac is a macOS menu-bar app (MenuBarExtra, no Dock icon). AppState is a single @MainActor orchestrator that owns every service and is the only thing that calls between them. Everything left of the pipeline is the original capture-and-transcribe flow; everything from the pipeline onward is where post-ASR features (cleanup, dictionary fixes, snippets) live. PostProcessService is the only node in the app that ever opens a network socket, and it only ever talks to localhost.

Fig. 1 — component tree: menu-bar UI → AppState orchestrator → hotkey/audio/ASR capture chain → the 4-stage transcript pipeline → text injection, with History/Profiles/Settings and Command Mode as side branches. LM Studio is the one external, network-reachable box.

2 Sequence — an ordinary dictation

Left of the pipeline call is the original capture-and-transcribe flow, unchanged. From pipeline.run(...) onward is where post-ASR features live, and every one of them is allowed to fail safely: whatever the pipeline was handed is what gets injected if a stage declines, errors, or times out.

Fig. 2 — a full dictation round trip: hotkey → audio capture/VAD → ASR (model selection shown) → the four pipeline stages in their fixed order → text injection → history record. Dashed arrows are returns; the red arrow is the one network call in this whole flow.

ASR (WhisperKit / CoreML / Neural Engine, short utterance)~0.3–2s depending on model sizebounded on the input side by maxRecordingDuration (default 180s)

These are order-of-magnitude figures, not benchmarked numbers — actual per-dictation timings are recorded per run in HistoryRecord.asrMillis / postProcessMillis and visible in the History view.

Identity-fallback, concretely: with post-processing off (its shipped default) and no Dictionary entries or Snippets defined, the entire pipeline is a no-op — the raw ASR transcript is what gets injected, byte for byte. Turning post-processing on doesn't remove that guarantee: any failure mode (LM Studio unreachable, non-2xx response, bad JSON, empty or disproportionate output, timeout) makes PostProcessStage return the input text unchanged. There is no error dialog for this — the user just gets the raw transcript instead of the cleaned one, exactly as if the feature were off.

3 Sequence — Command Mode

Command Mode is a separate route (CommandModeCoordinator), not part of TranscriptPipeline, and it inverts dictation's failure philosophy. Dictation's safe fallback is always "keep the raw transcript." Command Mode's equivalent fallback would be pasting the spoken instruction itself over the user's selected text — destructive — so instead any failure at all aborts and changes nothing. Every red box below is a distinct exit that leaves the document untouched.

Fig. 3 — Command Mode's flow with all six abort exits shown at the point they trigger, plus the one outcome (write-unverified, amber) that is not a guaranteed no-op. There is also a seventh, unshown exit: if a force-recovery, device change, or newer gesture happens while the LLM call is in flight, the stale result is discarded rather than written into whatever the user has since selected or opened.

The selected text itself is held only in memory for the length of one operation (CommandModeCoordinator.snapshot), is never logged beyond its character count, and there is no field on HistoryRecord capable of holding it or the rewrite — Command Mode writes nothing to History at all, by design.

4 The models — what's on disk, what's in LM Studio

Three models, three different lifecycles. Two live in a WhisperKit-managed folder on this Mac; the third is a separate, user-installed application VocaMac only ever talks to over loopback.

ModelSizeRuns onUsed forDefault?
ivrit.ai whisper-large-v3-turbo ~1.5 GB CoreML via WhisperKit → Neural Engine ASR, Hebrew-tuned No — manual
openai whisper-large-v3 (compact) 626 MB CoreML via WhisperKit → Neural Engine ASR, general fallback/legacy Yes — shipped default
Qwen3-4B-Instruct (MLX, 4-bit) ~2.28 GB MLX on Apple Silicon, served by LM Studio Transcript cleanup + Command Mode rewrites Yes — the only LLM backend

Fig. 4 — the two ASR models share a folder WhisperKit manages; the ivrit.ai one is placed there by hand and never offered a download button. Qwen3-4B lives entirely inside a separate application.

Why the ivrit.ai model needs manual placement: WhisperKit's own recommendedModels() API can never endorse a model it doesn't know about, so ModelManager.isModelSupported(_:) special-cases this one entry to report support based on on-disk presence of the tokenizer files instead of WhisperKit's endorsement. No download button is ever shown for it; once the user places the model folder there themselves, it appears as a normal, loadable entry in the picker.

RAM footprint, approximate, at inference time: the compact 626 MB ASR model needs roughly 5 GB resident; the ivrit.ai model roughly 6 GB. Qwen3-4B in LM Studio is a separate process with its own footprint. Running a large ASR model and the LLM concurrently on a 24 GB Mac is a flagged memory-pressure risk in the architecture notes — the app does not run ASR and LLM inference at the same instant, but both stay resident in memory.

5 Privacy and data flow

The rule underneath all of this (AD-5): cursor context and Command Mode's selection are both captured once, at the moment an action begins, carried on an in-memory value for exactly the one operation that needs them, and explicitly cleared on every exit path — success, failure, timeout, force-recovery, device change, or a superseding new gesture. Neither ever has a field to be written into on HistoryRecord.

Fig. 5 — three zones: what's written to disk (all local, owner-only permissions), what only ever exists in memory for one operation, and the single loopback network path. There is no fourth zone — nothing in this app reaches the public internet.

What does get written to History: the raw ASR transcript, the final (post-pipeline) text, which app it targeted, which Profile resolved, which model transcribed it, per-stage timings, and whether any stage had to fall back. Command Mode writes nothing to History at all — by design, since there is no field capable of holding a selection or a rewrite safely.
