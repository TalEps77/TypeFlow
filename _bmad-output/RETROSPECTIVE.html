What worked

Practices worth repeating, each tied to where it paid off.

Pre-converted ivrit.ai model found, not built

The Hebrew ASR agent found an already-CoreML-converted ivrit.ai Whisper fine-tune matching WhisperKit's expected model layout — matching the "prefer pre-converted, saves hours" fallback plan. No local conversion pipeline was needed for Epic 1's entire premise.

ivrit-model-report.md:3,99-100

Staggered dev → adversarial-review → fix waves, per epic

Each epic's code was written by one agent and reviewed by a different one that never wrote it, with adversarial review deliberately run on Opus 5 regardless of which model wrote the code under review. The pattern repeats across all 8 epics: Story N.M → Apply Epic N adversarial-review fixes.

What hurt

Two items are file-verified; two are carried as the orchestrating session's own account, flagged where evidence could not independently confirm them.

727 tests written blind — first real run found a production deadlock plus ~10 test bugs

test_run1.log: the suite's first-ever execution, 727 tests, 1 skipped, 14 failures. Isolated one genuine production bug in e473210: AudioEngine.processAudioBuffer read a lock-guarded flag from the real-time render thread while stopRecording/forceReset held that same lock inside engine.stop() — a true mutual deadlock that hung swift test indefinitely. The rest were test bugs: stale pre-fork default expectations, Swift 6.3 type-inference breakage, shared @AppStorage scratch state leaking between tests, an inverted assertion, and a mock whose fallback semantics diverged from the real pipeline. All fixed in one commit; test_run3.log/test_run4.log confirm 727 green twice in a row.

test_run1.log; commit e473210; test_run3/4.log

Ad-hoc signing forced a TCC reset on every rebuild

Grants are keyed to the app's on-disk identity/cdhash, so the stuck-permission hint, install.sh, uninstall.sh, and the README all have to lead with "remove the old row, then re-add." Confirmed independently for the rebrand itself: "User is re-granting anyway (cdhash reset)." tccutil reset is noted as unreliable for Accessibility specifically.

Why this epic exists

The re-verification round traced all 171 ACs in epics.md to their implementing code and tests: 106 SATISFIED, 46 PARTIAL (under-verified or a documented deviation), 2 VIOLATED, 10 UNVERIFIABLE (manual-only by nature), 7 superseded/cut. The 2 VIOLATED ACs, plus a CI hazard and an epic-8 carryover mechanical defect found in the same pass, are Epic 9's four stories.

The clearest evidence that the added per-story review layer earns its keep: Story 9.2's own first fix for the loopback-enforcement violation introduced a live HTTP redirect exfiltration bypass (a 307/308 from the trusted, configured endpoint could re-POST the full transcript off-box). The original 8-epic run didn't leave this behind — the first Epic 9 review pass did, and the second, independent reviewer caught and closed it before it could ship. That's the review discipline this epic exists to restore, working exactly as intended.
