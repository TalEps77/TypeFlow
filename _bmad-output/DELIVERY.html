01

The original request

Tal wanted the Wispr Flow experience — dictate anywhere on the Mac, get clean text — without paying for it, without an account, and without audio, screen contents, or cursor text ever leaving the machine. The vehicle was local-whisper, a fork of the VocaMac app already installed here (Swift/SwiftPM, WhisperKit/CoreML, ~9,500 LOC), with two things layered on its working Whisper-to-cursor pipeline:

  • A Hebrew-first ASR upgrade — an ivrit.ai Whisper fine-tune, expected to beat Wispr Flow's cloud model on Hebrew specifically.
  • A small local LLM (Qwen3-4B via LM Studio, loopback only) doing what Wispr Flow's cloud layer does — strip fillers, punctuate, resolve self-corrections, adapt tone per app — with nothing leaving the device.

All three roadmap phases from the pre-existing gap-analysis doc — Hebrew accuracy + LLM cleanup + history; per-app profiles + dictionary + snippets; command mode + better voice detection + streaming — were approved together. Nothing was deferred to "maybe later."

02

The plan

Standard BMAD workflow, run end-to-end through subagents, with the orchestrator only routing and synthesizing between them:

  1. Gap-analysis doc (pre-existing, 26 Jul 2026) — "VocaMac vs Wispr Flow" — the discovery input; settled stay-on-VocaMac, LM Studio + Qwen3-4B, and the ivrit.ai model up front.
  2. PRD — vision, target user, 25 functional requirements across 9 features, non-goals, success metrics, cross-cutting NFRs, settled decisions.
  3. Architecture — 13 binding decisions (AD-1 … AD-13): one pipeline seam in AppState, identity-on-failure as a tested guarantee, stage ordering, protocol + mock per service, cursor context never persisted.
  4. Epics & stories — 7 epics, 27 stories, each with Given/When/Then acceptance criteria and explicit verification steps.
  5. Per-epic development — one dev agent per epic, stories implemented in dependency order.
  6. Adversarial review per epic — a separate reviewer agent, never the one that wrote the code, tested each epic against its own stated acceptance criteria.
  7. Fix cycle per epic — every blocker and major applied, with judgment-call deviations documented rather than hidden.

04

What was built, and why

Each epic below closes a specific Wispr Flow parity gap. Expand any epic for its commits and the sharpest thing adversarial review caught there.

blocker found & fixed major found & fixed clean / no code change needed
E1Hebrew ASR Accuracy▸

Closes: the single biggest gap-and-win against Wispr Flow — better Hebrew, locally, for free. Registers the side-loaded ivrit.ai CoreML model in the picker without offering a broken download, and records per-stage latency so model choice is measured, not guessed.

4fffa11f1a48623ffe21a fixes5bfa235
Review caught: onboarding still offered "Try Anyway → Download" for the sideload-only entry — it would fabricate a ~15s progress bar, then fail. The generic startup-fallback logic could also silently switch any user onto the Hebrew model by picking the catalog's last entry, and a removed model could show "Active" and "Not Installed" at once.
E2LLM Post-Processing▸

Closes: the actual product gap — raw transcript into send-ready text. PostProcessService calls LM Studio over loopback with a hard deadline; any failure falls back to the raw transcript silently, so the worst case is exactly today's behavior.

ff8e402a545b32ef73508256bc54058d717 fixes
Review caught the project's most consequential blocker: the validator decoded finish_reason for nothing — a reply truncated by the server's token cap was accepted and injected as complete, silently deleting up to half a long sentence. Also found: no similarity check at all between input and output, so a model that answered the transcript as a question, or echoed a few-shot example verbatim, passed straight through to the cursor.
E3Transcription History▸

Closes: nothing was previously recoverable — no re-paste, no undo, no way to see what the LLM changed. Adds a local JSON store, a browsable/searchable history view, re-paste, and best-effort undo.

5a6715882eecffe4fb4cf741a8505bfa235ce90692 fixes
Review caught the sharpest blocker in the project: undo re-read whatever text currently sat before the caret and deleted that many characters, with no check it was still the app's own text — typing three characters after a dictation, then hitting undo, deleted eight characters of the user's own typing. A second blocker: a unit test posted a real system-wide ⌘Z into whatever app the developer's machine had focused, meaning running the test suite could silently undo the developer's own work.
E4Profiles & Cursor Context▸

Closes: the same utterance shouldn't read the same in Slack and in a legal document. ProfileManager resolves the frontmost app to a Profile; optional Cursor Context feeds surrounding text to the LLM — off by default, as the most privacy-sensitive capability in the product.

2f33094d02a1e8b14d28743163c262fee31fa472d0 fixes
Review caught the project's most subtle privacy hole: the LLM could "launder" cursor context — echo 80 characters of the surrounding document back into its output — and both safety validators passed it, because the echo was itself plausible-length and similar-enough. That laundered context got typed into the user's document and written to history.json, breaking the "never saved to history" promise. Also found: captured context could sit in memory indefinitely if a headset dropped mid-dictation.
E5Dictionary & Snippets▸

Closes: a mis-transcribed domain term can be fixed once and stay fixed; a spoken cue expands into boilerplate without the LLM. Requires correct Hebrew normalization first, since edit-distance matching is the whole mechanism.

3dee1ed02cf78a8d1f4e0a4c529dde654faa0bd11118e2ae1 fixes
Review caught: matres-lectionis normalization (ו/וו, י/יי) collapsed genuinely distinct Hebrew words together — מוות/מות, עוול/עול — so one added trigger silently rewrote the other word everywhere. The shipped fuzzy-match threshold also landed exactly on Hebrew's productive -ת inflection, so pairs like עובד→עובדת ("worker" → "female worker") cleared the fuzzy tier and were silently swapped.
E6Command Mode▸

Closes: select text, speak an instruction, get a rewrite in place — the one flow that must never fall back, since pasting a raw instruction over a selection would be destructive.

d564e0c370183e4572a987d96571593678c fixes
Review caught: the second hotkey was never wired up on a normal app launch — only on first-permission-grant and inside settings-change handlers — so enabling Command Mode and relaunching left a toggle reading "ON" over a feature that was completely dead. A second blocker: under a slow-LLM-then-retry sequence, a stale rewrite from an abandoned operation could still land on a freshly re-selected paragraph, while the app told the user "nothing was changed."
E7Responsive Capture (VAD)▸

Closes: the fixed RMS amplitude threshold cut off quiet speech and natural Hebrew pauses as if they were silence. Replaces it with WhisperKit's EnergyVAD and enables .vad chunking for parallel long-recording transcription. Streaming partial results, the third item here, was spiked and explicitly cut — see §7.

cd223b9f2d826c908f08c226040e fixes
Review caught the epic's headline bug: the VAD's 100ms frame length never actually engaged, because the audio tap's buffer size at real hardware sample rates converts to fewer samples than one frame needs — the "voice activity detector" was silently degenerating to whole-buffer RMS the entire time. The dev agent's own verification harness missed this because it replayed audio in differently-sized chunks than the real tap ever produces — the class of bug that only shows up by reasoning about the real buffer math, not a convenient synthetic test.

A few findings across all epics were resolved as documented, deliberate deviations rather than code changes — where a protocol lives, or that translate/rewrite-style Profile prompts get rejected by the safety validator by design. Those are recorded in epics.md, not swept under the rug.

05

Delivered state

  • /Applications/VocaMac.app, version 0.8.0-local-hebrew, installed and running.
  • ivrit.ai Hebrew ASR (~1.5GB), side-loaded, selectable from the model picker — meaningfully better Hebrew accuracy than Wispr Flow's cloud model.
  • LLM cleanup via LM Studio running qwen3-4b — off by default, enable it in the Post-Processing settings tab. Degrades to today's raw-transcript behavior whenever LM Studio isn't reachable.
  • History — every dictation saved locally; browse, search, re-paste, and best-effort undo, from the menu bar and the history view.
  • Per-app Profiles with optional Cursor Context (off by default) — casual tone in chat apps, formal in mail, identifier-shaped in code editors, out of the box.
  • Hebrew-aware Dictionary + Snippets + correction learning — Dictionary and Snippets on by default and mechanical (no LLM needed); correction learning is off by default.
  • Command Mode — select text, speak an instruction, get a rewrite in place. Off by default; needs enabling and a second hotkey in settings.
  • EnergyVAD auto-stop + .vad chunking — fixes cutting off quiet speech and natural pauses; speeds up long recordings.

Everything above is local and offline-capable. With every new feature off, the app behaves byte-for-byte identically to the pre-project baseline — this "identity guarantee" was a first-class, tested architectural requirement, not an afterthought.

07

Left out / future

Streaming partial results — cut, not missed

Spiked, then explicitly cut. WhisperKit's AudioStreamTranscriber constructs and owns its own AVAudioEngine, input node, and tap — in direct conflict with the app's existing AudioEngine, which the rest of the app depends on for Bluetooth handling, device selection, and VAD. Using it would mean either an architecture-violating rewrite of audio capture, or reimplementing WhisperKit's segment logic from scratch. Documented as a spike result in epics.md, not silently dropped.

Mobile, sync, teams

Out of scope by explicit PRD decision, not time pressure. Multi-machine needs are served by JSON export/import of Profiles, Dictionary, and Snippets.

A smaller int8 ivrit.ai model

Available on Hugging Face if the ~1.5GB footprint alongside a loaded LLM ever becomes a memory concern on this 24GB machine.

Translate/expand-style Profile prompts — rejected by design

The safety validator that stops the LLM going off the rails is tuned for cleanup-style prompts. A Profile asking for translation or heavy rewriting will reliably get its output rejected and fall back to the raw transcript. Known, documented limitation — the UI states the constraint rather than pretending those Profile styles work.

.vad chunking tail-drop

Can drop up to ~1 second off the tail of recordings over 30 seconds. In push-to-talk use, releasing the key right after the last word can lose the final syllable. Documented, not fixed — no code fix short of pre-padding the chunk window.
